To increase response time we will use caching 

CACHE :-
- Temporary storage 
- Stores - expensive response result , frequently access data 

So now if webserver required any data it first check cache , if not available then DB

![[Pasted image 20260707150959.png|Pasted image 20260707150959.png]]

We interact with cache using cache api .

Things  to consider for using cache ?
- Data read frequently + less modification 
- Expiration policy : should not be too low(data reload frequently from DB) Or too high (Stale data)
- Consistency btw db and cache 
- Multiple cache severs across different data centers SPOF (Single point of failure)
- Eviction policy : when cache is full (LRU , LFU , FIFO)
