-> As our service grow , our data grow ,now database will overload , now we have to scale database server .

Database Scaling : 
1. Vertical scaling
2. Horizontal scaling (Sharding)

Vertical Scaling :  more power(CPU ,ram ,disk)
Drawback : 
- hardware limits 
- Single point of failure(SPOF)
- Costly

Horizontal scaling (Sharding) : Adding more servers 

![[Pasted image 20260708085525.png|Pasted image 20260708085525.png]]

In horizontal to decide to which server we will add data to server ?
we will use Sharding key (hash function) eg :  user_id % (no of server )
We must select Sharding key carefully so that data distributed evenly .

Drawbacks of Sharding :
- Resharding : 
	1. When shard can no longer hold more data . 
	2. shard exhaustion due to uneven distribution . It will require updating sharding function then move data around .
