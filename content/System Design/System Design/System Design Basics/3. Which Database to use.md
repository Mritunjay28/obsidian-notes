| Relational Databases             | Non-Relational Databases                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------------------- |
| SQL database OR RDBMS            | NoSQL Database                                                                                        |
| eg : MySQL , Oracle , Postgres   | eg : mongoDB,etc                                                                                      |
| Represent data in table and rows | Grouped into 4 types :<br>1) Graph store<br>2) Key-Value Pair<br>3) Column Store<br>2) Document Store |
| Can perform JOIN Operations      | Cannot perform JOIN Operations                                                                        |


WHEN TO USE WHAT ?

-> SQL Database Works for most of scenario 

BUT WE SHOULD USE NoSQL Database WHEN : 

1. Flexible schema  : it allow documents stores only what it needs 

```
    Phone
	{ name:"iPhone", price:80000, ram:"8GB", storage:"256GB"}
	Shoes
	{ name:"Nike", size:9, color:"Black"}
	Book
	{ title:"Clean Code", author:"Robert Martin", pages:450}
	
	IN SQL will require lots of null value 

```
2. Massive write traffic : as NoSQL uses horizontal scaling it allow us to have multiple servers to distribute data 
3. The structure (schema) of the data changes frequently.

```
   Today: {  "name": "John"}
   Next month: {  "name": "John",  "skills": ["Java", "Spring"]}
   Next year: {  "name": "John",  "skills": ["Java"],  "portfolio": "..."}

   With many NoSQL databases, we don't need schema migrations for every change.
```
4. . Doesn't have many joins (Relationships are minimal)
5. Semi-structured or unstructured data
6. Application require super low latency
