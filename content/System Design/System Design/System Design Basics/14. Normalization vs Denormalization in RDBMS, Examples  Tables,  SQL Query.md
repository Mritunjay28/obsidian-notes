DE-Normalization :
- Deliberately introduce redundancy into a database table 
- opposite of normalization 
- we do it so that 
	  1. Improved performance query (No join)
	  2. Simplified query 
	  3. Reduce joins
	  4. Best for - > Read intensive scenario
- But it have it's Cons 
	1. Redundancy - memory waste 
	2. Inconsistent data  (may forget to update for some scenario )
	3. update/write operation - extremely slow as have to update at multiple places
