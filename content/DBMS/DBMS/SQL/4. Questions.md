## 1. SQL DIVISION Implementation Techniques

****Given two relations(tables): R(x,y), S(y).****

- ****R and S****: tables
- ****x and y****: column of R
- ****y****: column of S

****R(x,y) div S(y)**** means gives all distinct values of x from R that are associated with all values of y in S.

```
SELECT x
FROM R
GROUP BY x
HAVING COUNT(DISTINCT y) =
(
    SELECT COUNT(*)
    FROM S
);
```

# 2. SQL MINUS Operator
The MINUS operator is used with two `SELECT` statements to return only those rows from the first query that are not present in the second. It filters out all common rows and keeps only the unique rows from the first result set.
```
SELECT NAME, AGE, GRADE
FROM Table1

EXCEPT

SELECT NAME, AGE, GRADE
FROM Table2;
```

# 5. Outer Join for "Never Happened" Records

```
Find customers who never placed an order:
SELECT c.name
FROM Customers c
LEFT JOIN Orders o ON c.id = o.customer_id
WHERE o.customer_id IS NULL;
```

# 6. Conditional Aggregation (`CASE WHEN` inside `SUM`/`COUNT`)

```
Very common when asked to pivot rows into columns or calculate percentages/rates in a single scan:

SELECT 
    user_id,
    COUNT(*) AS total_requests,
    SUM(CASE WHEN status = 'confirmed' THEN 1 ELSE 0 END) AS confirmed_count,
    ROUND(AVG(CASE WHEN status = 'confirmed' THEN 1.0 ELSE 0.0 END), 2) AS confirmation_rate
FROM Confirmations
GROUP BY user_id;
```

# 7. Consecutive Rows / Streaks (`LAG` and `LEAD`)

```
Find numbers that appear at least 3 times consecutively:

WITH PrevNext AS (
    SELECT num,
           LAG(num, 1) OVER (ORDER BY id) AS prev_num,
           LEAD(num, 1) OVER (ORDER BY id) AS next_num
    FROM Logs
)
SELECT DISTINCT num AS ConsecutiveNums
FROM PrevNext
WHERE num = prev_num AND num = next_num;
```

# 8. `LEFT JOIN`: `ON` vs. `WHERE` Trap:
```
-- CORRECT: Filters Orders BEFORE joining; preserves Customers with 0 orders (o.amount is NULL)
SELECT c.id, o.amount
FROM Customers c
LEFT JOIN Orders o ON c.id = o.customer_id AND o.amount > 100;

-- TRAP: Filters AFTER joining; since o.amount > 100 is UNKNOWN for NULLs,
-- this wipes out all unmatched rows and turns your LEFT JOIN into an INNER JOIN!
SELECT c.id, o.amount
FROM Customers c
LEFT JOIN Orders o ON c.id = o.customer_id
WHERE o.amount > 100;
```

# 9. `COALESCE()` & `NULLIF()`
- **`COALESCE(val1, val2, ..., default_val)`:** Returns the first non-`NULL` value in the list. Essential for replacing `NULL` output from `LEFT JOIN` or aggregates with `0`:`SELECT c.name, COALESCE(SUM(o.amount), 0) AS total_spent ...`
    
- **`NULLIF(expr1, expr2)`:** Returns `NULL` if `expr1 = expr2`, otherwise returns `expr1`. Essential for **preventing division-by-zero errors**:`SELECT revenue / NULLIF(units_sold, 0) AS price_per_unit ...` (Since dividing by `NULL` safely returns `NULL` instead of crashing the query).

# 10. Running Totals & Moving Averages (Window Frames)
```
Interviewers love asking for a **7-day moving average** or a **cumulative running total**:

SELECT 
    visited_on,
    amount,
				    -- Cumulative Running Total
    SUM(amount) OVER (ORDER BY visited_on) AS running_total,
				    -- 7-Row Moving Average (Current row + 6 preceding rows)
    ROUND(AVG(amount) OVER (
        ORDER BY visited_on 
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ), 2) AS moving_avg_7d
FROM CustomerSales;
```
